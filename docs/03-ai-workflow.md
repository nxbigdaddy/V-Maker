# AI 生产工作流

## 1. 总流程

```mermaid
flowchart LR
    A[故事输入] --> B[故事分析]
    B --> C[分集与大纲]
    C --> D[项目圣经]
    D --> E[参考资产]
    E --> F[分集剧本]
    F --> G[分镜脚本]
    G --> H[低清故事板]
    H --> I[临时配音与动态分镜]
    I --> J{审核}
    J -->|修改| F
    J -->|通过| K[正式关键帧]
    K --> L[镜头视频]
    L --> M[对白/口型/音乐/音效]
    M --> N[时间线合成]
    N --> O[自动与人工质检]
    O --> P[MP4或剪映草稿]
```

## 2. 工作流原则

- 每个阶段接收结构化输入并产生结构化输出；
- 文本字段用 JSON Schema 校验；
- 媒体输出必须注册到资产库；
- 上游批准版本是下游唯一默认输入；
- 对高成本节点设置预算闸门；
- 失败重试只重做最小受影响范围；
- 任何自动降级必须记录并在 UI 标示。

## 3. 阶段定义

### W01 故事导入与分析

输入：原始故事、用户目标。

输出：

- 标题、类型、主题；
- 世界观；
- 人物、地点、道具候选；
- 故事节拍和冲突；
- 内容风险；
- 分集建议；
- 不确定项。

校验：人物 ID 唯一、故事节点覆盖原文、无法确认的信息不得擅自写成事实。

### W02 分集规划

输入：故事分析、时长约束。

输出每集：标题、梗概、开场钩子、核心冲突、结尾钩子、预计时长和覆盖的原文范围。

时长估算：对白时长 + 动作时长 + 建立镜头 + 转场余量。

### W03 项目圣经

建立并版本化：

- 全局风格；
- 世界观规则；
- 角色外观、性格和声音；
- 场景；
- 道具；
- 允许与禁止项。

项目圣经必须先批准，再进入批量正式生产。

### W04 参考资产生成

对每个主要资产生成多个候选：

1. 提示词编译；
2. 调用生图 Provider；
3. 视觉模型检查；
4. 候选评分；
5. 用户/规则批准；
6. 建立资产版本并锁定。

主要角色至少应有主参考图、全身图、近景图和常用表情。多集项目建议进一步使用 LoRA、IP-Adapter 或 3D 资产，但它们不是 MVP 的前置条件。

### W05 剧本生成

每场包含：

- 地点和时间；
- 出场人物；
- 场景目的；
- 动作；
- 对白、说话人和情绪；
- 预计时长；
- 与前后场的连续性。

重要台词可由用户锁定，后续节奏优化不得自行改写。

### W06 分镜生成

每个镜头包含：

- 镜头 ID；
- 所属集与场；
- 叙事目的；
- 景别、角度、构图、运镜；
- 角色、场景、道具引用；
- 动作与情绪；
- 对白引用；
- 时长；
- 连续性约束；
- 推荐制作策略；
- 复杂度、成本和风险。

制作策略可以是：

- `text_to_video`；
- `image_to_video`；
- `start_end_frame_video`；
- `talking_head`；
- `static_pan_zoom`；
- `composite_effect`；
- `imported_media`。

### W07 动态分镜

正式视频前先生成低清图、临时 TTS 和代理时间线。动态分镜通过后，锁定：

- 镜头顺序；
- 大致时长；
- 对白文本；
- 场景覆盖；
- 是否有叙事缺口。

正式生产后仍允许修改，但 UI 必须显示返工范围和费用。

### W08 正式关键帧

提示词不是单段字符串，而是编译结果：

```text
全局风格层
+ 场景资产层
+ 角色/道具资产层
+ 镜头构图层
+ 连续性层
+ 技术参数层
+ 负面约束层
```

保存每层文本，便于定位问题。关键帧通过身份、构图、肢体、风格和安全检查后才能进入视频生成。

### W09 视频生成

提交内容：

- 起始帧，可选结束帧；
- 运动提示；
- 镜头运动；
- 时长和画幅；
- 参考资产；
- 禁止变化项。

视频一般以 2–8 秒镜头为单位。长动作应自动拆镜，复杂互动失败时优先改分镜，而非无限重试。

### W10 声音生产

顺序建议：

1. 最终对白；
2. TTS；
3. 获取真实语音时长；
4. 调整镜头或停顿；
5. 必要时口型同步；
6. 环境音和动作音效；
7. 音乐规划；
8. 响度与混音。

对白、音效和音乐必须保留独立轨道。

### W11 时间线和合成

由程序依据内部时间线 JSON 执行，不让 LLM 直接拼接二进制媒体。合成包括：

- 统一分辨率、帧率和色彩空间；
- 裁切片段；
- 转场；
- 音频混合；
- 字幕；
- 片头片尾；
- 编码输出。

### W12 最终质检

检查：

- 黑帧、静音、损坏媒体；
- 音画长度和同步；
- 镜头顺序；
- 字幕越界；
- 响度峰值；
- 角色和道具连续性；
- AI 变形与闪烁；
- 内容安全；
- 输出规格。

## 4. 审核门

| 审核门 | 必须确认内容 | 通过后的影响 |
|---|---|---|
| G1 | 分集大纲 | 允许建立项目圣经和剧本 |
| G2 | 风格与主要角色 | 允许批量分镜图生产 |
| G3 | 动态分镜 | 允许高成本视频任务 |
| G4 | 最终预览 | 允许正式导出 |

草稿模式可以按规则自动通过，标准模式等待用户，专业模式可增加场景级审核。

## 5. 自动质检与重试阶梯

```text
失败 1：保留方案，修正提示词或 seed 后重试
失败 2：更换候选参考图或同能力 Provider
失败 3：降低动作、运镜或人物数量
失败 4：把镜头拆成两个短镜头
失败 5：降级为静态图运镜/合成方案
仍失败：暂停并请求人工处理
```

每一级都受以下限制：

- 最大尝试次数；
- 单镜头预算；
- 项目预算；
- Provider 限流；
- 任务超时。

## 6. 变更传播

不是所有上游变化都应重做所有下游。

示例：

- 修改错别字但语音不变：只更新剧本文档；
- 修改对白：使对应 TTS、口型、字幕和时间线失效；
- 替换角色外观：使引用该版本的关键帧和视频标记为“过期”；
- 调整镜头时长：通常只影响时间线、字幕和音乐区间；
- 更换视频候选：只重建代理和最终合成。

系统应维护依赖边并显示 `stale` 状态，而不是立即自动删除旧结果。

## 7. 多集工作流

项目级资产由所有集继承：

```text
项目圣经 v3
├── EP01 使用角色 A v2、场景 M v1
├── EP02 使用角色 A v2、场景 N v1
└── EP03 使用角色 A v2、场景 M v1
```

每集可以有独立状态和导出版本。升级项目圣经时，已发布集保持原绑定，新集默认使用最新批准版本。

## 8. 一键自动制作流水线（已实现）

MVP 已把第 1 节的总流程收敛成一条可一键执行的流水线，用同一个持久任务承载全部阶段：

```text
analysis → bible → production_plan → demo_media → timeline → export
故事分析 → 项目圣经 → 剧本与分镜 → 演示素材 → 时间线 → 导出
```

### 8.1 任务与阶段状态

- 任务类型 `pipeline`，状态使用通用任务状态机 `queued / running / paused / completed / failed / canceled`；
- `paused` 专用于审核门：阶段已产出、但未获人工确认；
- 阶段进度写入任务的 `payload_json`：`stage_index`（下一个要执行的阶段下标）与 `completed_stages`；
  因此进程重启后 `recover_running` 把任务放回队列，下一次执行会从断点继续，不会重跑已完成阶段；
- `progress` 与 `message` 每阶段更新，GUI 直接展示「正在执行：<阶段名>」。

### 8.2 审核门语义

审核门设在 `bible` 与 `production_plan` 之后（`require_review=true` 时生效）。

关键约定：**暂停不得让进度倒退**。

- 阶段开始前：仅把该阶段对应的 `workflow_stages` 从 `pending` 置为 `in_progress`，已 `completed` 的键永不回退；
- 阶段完成后：该阶段键置 `completed`，并补齐它前面仍是 `pending` 的键；
- 命中审核门且还有后续阶段时：任务置 `paused`，`workflow_stages` **保持生成器自报的状态**，不再改写。
  审核状态由任务承载（`status=paused` + 中文 message），而不是通过回退工作流阶段来表达；
- `resume` 越过审核门时，被视为人工批准，此时才把该阶段键补为 `completed`。

映射关系（`workflow_stages.stage_key`）：

| 流水线阶段 | workflow 键 |
| --- | --- |
| `analysis` | `story_analysis` |
| `bible` | `project_bible` |
| `production_plan` | `screenplay`、`storyboard` |
| `demo_media` | `assets`、`audio` |
| `timeline` | `timeline` |
| `export` | `export` |

### 8.3 取消与续跑

- `POST /api/tasks/{id}/cancel`：任务置 `canceled`；执行器在每个阶段开始前重新读取状态，发现非 `running` 立即停止，且不会再写 `completed`；
- `POST /api/tasks/{id}/resume?execute=true`：仅 `paused` 可用，置回 `queued` 并由后端直接调度续跑（GUI 的「继续」按钮就是这一次调用）；
- `POST /api/tasks/{id}/retry?execute=true`：仅 `failed` / `canceled` 可用；
- 暂停与取消都会释放该任务的预算预留，`estimated_cost` 保留，续跑时重新预留，不会重复计费。

## 9. 素材内容服务（已实现）

素材库不再只显示文件路径，GUI 可以直接预览：

```text
GET /api/projects/{id}/assets/{asset_id}/versions/{version_id}/content
GET /api/asset-versions/{version_id}/content
```

安全约束：

1. 项目必须存在且未被软删除；
2. 资产必须属于该项目，版本必须属于该资产；
3. 相对路径解析后必须仍位于该项目目录内（禁止目录穿越）；
4. 文件必须存在，且**重新计算的 SHA-256 必须与数据库记录一致**（防止本地文件被替换）；
5. 响应使用 `inline`，并带 `X-Content-Type-Options: nosniff` 与
   `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox`，
   避免本地 SVG 被直接打开时执行脚本；
6. 支持 HTTP Range（206），音频可在浏览器中拖动播放。

任意一条校验失败都返回 404，不泄露存在性信息。
