# 决策记录与待确认问题

## 1. 已建议的关键决策

| 编号 | 决策 | 原因 |
|---|---|---|
| D-001 | 首版采用 Windows 桌面应用 | 便于管理媒体、FFmpeg 和剪映草稿 |
| D-002 | 镜头是最小生产与重跑单元 | 控制成本并支持局部修改 |
| D-003 | 项目圣经是跨集一致性的来源 | 避免角色、场景和声音漂移 |
| D-004 | 使用内部中立时间线 | 不绑定剪映，保证 MP4 和其他导出可扩展 |
| D-005 | 标准模式默认保留四个审核门 | 在成本和质量间平衡 |
| D-006 | 资产版本不可覆盖 | 保证追溯、比较和复现 |
| D-007 | Provider 按能力抽象 | 可替换 DeepSeek、Qwen Image、H3 等供应商 |
| D-008 | LLM 决策结构化，程序确定性执行 | 降低不可预测性和二进制操作风险 |
| D-009 | SQLite + 本地文件作为 MVP 数据底座 | 单用户部署简单，后续可迁移 |
| D-010 | 先稳定 MP4，再做剪映适配 | 剪映格式兼容风险高 |

## 2. 需要产品方确认的问题

### Q1：软件形态

建议：Windows 桌面优先。

待确认：是否还必须支持纯 Web？纯 Web 无法轻松访问本地剪映目录和 FFmpeg，需要本地 Agent。

### Q2：首个目标内容

待确认：

- 30–90 秒概念短片；
- 1–3 分钟故事视频；
- 5–10 分钟单集。

建议先选择 30–90 秒，验证闭环后扩展。

### Q3：画面类型

- AI 动画镜头；
- 静态漫剧 + 运镜；
- 两者混合。

建议允许混合，静态运镜是重要保底手段。

### Q4：首批 Provider

需获取每个实际 API 的：

- 官方接口文档；
- 鉴权方式；
- 请求/响应示例；
- 异步回调规范；
- 价格；
- 商用条款；
- 限流；
- 可用地区。

“Qwen Image”和“H3”需要进一步明确具体服务商、模型版本和 API 地址，避免只凭模型简称设计。

### Q5：TTS、音乐、音效

待选择具体服务商。MVP 可以先支持 TTS 和用户上传 BGM/SFX，AI 音乐生成作为 P1，以降低版权和流程复杂度。

### Q6：剪映版本

必须明确：

- Windows 还是 macOS；
- 国内剪映还是 CapCut；
- 精确版本号；
- 用户如何导入/发现草稿；
- 是否有官方 SDK 或交换格式。

在得到合法测试样本前，剪映导出只能标记为技术验证项。

### Q7：部署和隐私

- 所有元数据是否仅本地；
- 是否允许发送完整故事给第三方；
- 是否需要局域网/团队服务器；
- 是否有商业客户的数据驻留要求。

### Q8：质量与成本优先级

需要确定默认策略：

- 最低成本；
- 最快预览；
- 最佳质量；
- 三档可选。

建议三档可选，标准档为默认。

### Q9：人工确认粒度

建议默认审核：分集、项目圣经、动态分镜和成片。待确认是否还需要每个角色/每个场景单独签核。

### Q10：商业模式

- 本地软件买断；
- 订阅；
- 自带 API Key；
- 平台统一计费；
- 混合模式。

这会影响 Provider Account、成本账本和用户体系设计。MVP 最简单的是自带 API Key。

## 3. 技术验证清单

开始完整开发前必须验证：

- [ ] DeepSeek 或选定 LLM 能稳定输出约定 JSON Schema；
- [ ] Qwen Image 实际 API 支持目标参考图工作流；
- [ ] H3 的真实 API、时长、参考帧和回调机制；
- [ ] 选定 TTS 支持中文、多角色和情绪；
- [ ] FFmpeg 在目标 Windows 环境可再分发或引导配置；
- [ ] 目标剪映版本草稿结构和导入行为；
- [ ] 30–90 秒样片的真实生成成本；
- [ ] 长路径、中文路径和大文件稳定性；
- [ ] Provider 商业使用和数据条款。

## 4. 建议下一轮产物

确认上述问题后，可以进入可执行设计：

1. PRD v1 和明确的用户故事；
2. 页面线框图；
3. 数据库 ERD；
4. OpenAPI 规范；
5. Provider 插件接口定义；
6. Neutral Timeline JSON Schema；
7. DAG 节点和状态转换表；
8. 项目目录规范；
9. 剪映目标版本兼容性实验报告；
10. MVP 迭代 Backlog。

## 5. 建议最先确认的五个答案

1. 首版是否只支持 Windows 桌面？
2. 首版成片目标是 30–90 秒还是 1–3 分钟？
3. H3 具体是哪一个服务/接口？
4. 目标剪映的准确版本是什么？
5. 使用用户自己的 API Key，还是系统统一代付？

这些答案将直接影响技术选型、数据库、任务编排和商业成本模型。
