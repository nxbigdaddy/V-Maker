# 成片与剪映草稿导出

## 1. 双输出策略

系统支持两类交付：

1. **确定性成片**：通过 FFmpeg 合成 MP4/MOV；
2. **可编辑工程**：由内部中立时间线转换为剪映草稿，或导出通用时间线包。

内部不能直接以剪映格式作为唯一项目格式。剪映格式变化时，V-Maker 项目和 MP4 合成仍应可用。

## 2. 内部中立时间线

时间线包含：

- 统一 timebase；
- 画布、帧率和色彩配置；
- 视频、叠加、对白、音效、音乐、字幕轨；
- 每个 Clip 的源入出点和时间线入出点；
- 基础 transform、opacity、gain、fade；
- 转场；
- 字幕文本、样式和时间；
- Clip 到不可变资产版本的引用。

时间使用整数 tick 或有理数，不使用浮点秒，防止长时间线累计误差。

## 3. FFmpeg 成片流程

### 3.0 已实现并实机验证的部分（2026 迭代）

上面 3.1–3.6 是设计意图；这一节记录**现在真正跑通到什么程度**。

**FFmpeg 定位顺序**（`MediaRepository._ffmpeg()`，诊断接口与导出共用同一函数）：

1. `VMAKER_FFMPEG_PATH`（必须指向真实存在的文件）；
2. 系统 `PATH` 里的 `ffmpeg`；
3. 可选依赖 `imageio-ffmpeg` 自带的二进制（`pip install "v-maker[ffmpeg]"`）。

装了第 3 项就不必自行安装 FFmpeg；三者都没有时导出**如实回退**成通用草稿包，并在 warning 里说明原因。

**实机验证结果**（本机无系统 FFmpeg，用 `imageio-ffmpeg` 的 ffmpeg 7.1）：

- 镜头素材为位图时：产出可解码的 H.264 + AAC MP4，`ffmpeg -f null` 解码零错误，时长与时间线一致；
- **画布跟随项目宽高比**：16:9 → 1920x1080，9:16 → 1080x1920，1:1 → 1080x1080。此前这里硬编码 1280x720，竖屏项目会拿到横屏成片（已修，并有回归测试）；
- 素材不是位图时（例如你自己的 provider 返回 SVG）：FFmpeg 没有 SVG 解码器，导出**不会**假装成功，而是回退成通用草稿包，并给出可执行的原因（哪个镜头、什么格式、该怎么办）。

**默认 demo 素材是位图**：占位图由标准库手写 PNG 编码生成（七色测试卡 + 镜头号 + NOT AI 告示），不引入新依赖。因此**未配置任何 provider 的新项目也能直接产出真实 MP4 与有内容的剪映草稿**——实机验证见 `scripts/check_live_jianying_demo.py`。

**依赖 ffprobe 的部分尚未实现并已改道**：3.2 描述的用 ffprobe 读编码/帧率/SAR 等校验没有落地，因为 `imageio-ffmpeg` 不附带 ffprobe；成片自检改用 ffmpeg 自身完成（见 3.0 末尾），因此拿不到编码档次与 SAR/DAR 等字段。

**成片自检（已实现）**：合成之后必须**回读一遍**才能算完成——`verify_mp4_output()` 会：

1. 检查文件头是 MP4（`ftyp`）且不是空文件；
2. 用 `ffmpeg -v error -f null -` **完整解码**一遍（只读元数据发现不了中途截断或损坏的帧）；
3. 回读流信息，要求同时存在视频流与音频流；
4. 校验画布与项目宽高比一致；
5. 校验时长与时间线一致（容差 1.5s，覆盖容器时间戳的毫秒级舍入）。

任何一条不满足都会**如实失败**并回退成通用草稿包，而不是把一个没人能播放的文件标成 `completed`。代价是导出时间大约翻倍（多解码一遍），这是为「不交付坏成片」付的价钱。

**`ffprobe` 未使用**：文档早先设计的 ffprobe 深度校验没有落地，因为可选的 `imageio-ffmpeg` 轮子里**不含 ffprobe**。上面的自检改用 ffmpeg 自身完成，因此不依赖第二个可执行文件；代价是拿不到编码档次、SAR/DAR 等更细的字段。

### 3.1 Resolve

冻结一个 `timeline_version`，解析所有资产，检查文件存在、许可、批准状态和哈希。

### 3.2 Probe

用 ffprobe 获取真实：

- 编码；
- 分辨率和 SAR/DAR；
- 帧率/timebase；
- 时长；
- 音频采样率和声道。

不能只相信数据库中的 Provider 元数据。

### 3.3 Normalize

必要时统一：

- 像素格式；
- 分辨率；
- 帧率；
- 采样率；
- 声道；
- 色彩空间。

预览使用代理文件，正式输出使用原始批准资产。

### 3.4 Build Filter Graph

典型处理：

- `trim/atrim`；
- `setpts/asetpts`；
- `scale/pad/crop`；
- `fps`；
- `overlay`；
- `xfade`；
- `amix`；
- `loudnorm`；
- 字幕合成。

命令必须以参数数组执行，禁止把未经处理的路径拼成 shell 字符串。

### 3.5 Render

默认：

- MP4；
- H.264；
- AAC；
- yuv420p；
- 用户设定帧率；
- Web/移动端兼容 faststart。

可选高质量母版：ProRes 或 DNxHR，视平台编码器可用性决定。

### 3.6 Verify

- 可完整解码；
- 音视频时长在容差内；
- 无非预期黑帧和静音；
- A/V 同步；
- 字幕不越界；
- 响度和峰值符合设置；
- 输出分辨率/帧率/编码正确。

保存导出 manifest：输入哈希、FFmpeg 版本、滤镜图、参数和输出哈希。

## 4. 音频和字幕输出

建议同时输出：

```text
final.mp4
subtitles.srt
subtitles.ass（可选）
dialogue.wav
music.wav
sfx.wav
mix.wav
shot-list.csv
export-manifest.json
```

对白、音乐、音效先分别归一，再进行人声优先的 ducking 和最终响度处理。

## 5. 剪映草稿定位

剪映草稿导出用于“粗剪后继续精修”，首版只承诺基础能力：

- 主视频轨；
- 基础叠加轨；
- 人声、音乐、音效轨；
- 字幕；
- 入出点；
- 音量；
- 少量经验证的基础转场。

复杂特效、蒙版、跟踪、关键帧曲线、VIP 素材和剪映云素材不作为首版承诺。

## 6. 重要兼容性风险

剪映草稿格式和目录可能随操作系统、地区版本和应用版本改变，而且不应假设它是长期稳定的公开交换标准。潜在问题包括：

- JSON、数据库或其他文件结构变化；
- 资源 ID、哈希或内部校验变化；
- 绝对路径不可迁移；
- 字体、滤镜、贴纸、转场 ID 不存在；
- 时间单位或变速语义不同；
- 剪映升级后旧适配器失效；
- 修改用户现有草稿目录导致数据损坏；
- 逆向格式和分发兼容层可能存在许可/EULA 风险。

因此产品文案应写明“支持的剪映桌面版范围”和“实验性兼容”，而不是承诺所有版本。

## 7. Exporter 适配层

```text
Neutral Timeline IR
        ↓
Jianying Capability Check
        ↓
Compatibility Report
        ↓
Jianying Version Adapter
        ↓
Media Package + Draft Files
        ↓
Post-export Verification
```

接口建议：

```text
probeTargetVersion()
validateCapabilities(timeline)
mapProject(timeline, options)
packageMedia(assetVersions)
writeDraft(destination)
verifyDraft(destination)
```

适配器按 `OS + 剪映版本 + 草稿格式版本` 注册。

## 8. 导出策略

### 8.1 非破坏性

- 永远导出到新目录；
- 不直接修改用户已有草稿；
- 若用户选择剪映草稿根目录，先创建独立项目目录；
- 冲突时生成新名称；
- 提供完整 manifest 和备份提示。

### 8.2 媒体打包

建议复制/硬链接批准媒体到草稿包可控目录：

```text
JianyingExport/
├── DraftProject/
├── Media/
│   ├── Video/
│   ├── Audio/
│   └── Images/
├── Subtitles/
├── export-manifest.json
└── compatibility-report.html
```

若目标格式支持相对路径则优先使用；若必须使用绝对路径，导出报告明确说明不可直接迁移到另一台电脑。

### 8.3 不支持功能的处理

提供三种策略：

1. **降级**：高级转场改为淡入淡出；
2. **预渲染**：将复杂叠加片段烧成单一视频 Clip；
3. **忽略并报告**：保留基础内容并在报告列出缺失项。

不得静默丢失效果。

## 9. 通用降级出口

即使剪映适配失效，也必须输出：

- MP4 预览；
- 原始/代理媒体；
- WAV 分轨；
- SRT/ASS；
- 镜头清单 CSV；
- 中立时间线 JSON；
- 可选 FCPXML/EDL（后续）；
- 导出报告。

这样用户仍能在剪映或其他 NLE 中手工重建。

## 9.1 已实现：真实剪映草稿生成（pyJianYingDraft 0.3.0）

第 5–8 节描述的是设计意图；这一节记录**当前代码实际做到的事**，以及实测到什么程度。

导出接口 `POST /api/projects/{id}/exports` 接受可选 `format`：

```text
auto            默认：有 ffmpeg 出 MP4；否则库可用时优先出剪映草稿；再否则通用草稿包
mp4             显式要 MP4；无 ffmpeg 时保持原有语义（通用草稿包 + 说明），不会悄悄变成剪映草稿
portable_draft  通用草稿包（自包含 zip，始终可用）
jianying_draft  真实剪映草稿；库缺失 / 构建失败 / 产出为空时回退通用草稿包并写明原因
```

实现要点：

- 接入的是 **`pyJianYingDraft`（PyPI，当前 0.3.0）**，属可选依赖。库不可用时**不做任何假设**，
  一律回退到通用草稿包并说明原因，导出本身不会因此变成 `failed`；
- 素材选择顺序：该镜头最新的**视频**素材 → 最新的**位图**素材 → 该镜头被跳过并记录原因；
- **剪映不能导入 SVG**。默认 demo 占位图已经是位图（PNG），可以直接进草稿；如果**你自己的图像
  provider 返回 SVG**，这些镜头会被跳过，原因写进 `export_jobs.warning` 并逐镜头列出；
- **产出为零片段时拒绝交付空草稿**，改为回退通用草稿包并说明「为什么一个片段都没有」——
  一份没有任何片段的草稿不是可用产物；
- 画布按项目宽高比映射（16:9 → 1920×1080，9:16 → 1080×1920，1:1 → 1080×1080），fps 默认 30；
- 轨道布局：视频轨按镜头首尾相接无空隙，语音轨与文本轨与对应镜头对齐；
- 草稿名清理 Windows 非法字符并限长；**同名不覆盖**（改名加后缀），绝不破坏用户已有草稿；
- 配置 `VMAKER_JIANYING_DRAFTS_DIR` 后，会**额外**把草稿写进该目录（用户真实的剪映草稿根目录）。
  写不进去只记 warning，不影响导出成功。

**关于完整性保证的一条明确规则**：导出通用草稿包时，

- 素材文件**缺失** → 跳过该文件，写入 `manifest.skipped_files`，并**必须出现在导出 warning 里**；
- 素材**SHA-256 校验不通过** → **直接失败**。字节与记录不符意味着损坏或被改动，
  照常导出会让「SHA-256 校验」这条保证失去意义。

**未验证（已如实写入代码注释、诊断接口与 zip 内的 `jianying-draft-info.json`）**：

- 开发环境**没有剪映**，因此草稿能否被剪映正常打开**未经验证**；
- `draft_meta_info.json` 中 `draft_name` / `draft_fold_path` 为空（该库内置模板的原样行为），
  是否有影响**未确认**；
- 草稿中的素材是**绝对路径引用**，只在同一台机器可用；删除项目素材会让草稿失效；
- **不提供自动导出**：该库的自动导出（控制剪映 GUI）只支持剪映 6 及以下，与本项目无关，
  成片请在剪映里自行导出。

## 10. 剪映适配验证

每个受支持版本至少测试：

- 空项目；
- 单视频；
- 多视频顺序拼接；
- 多音轨；
- 中文字幕；
- 基础转场；
- 裁切和变速；
- 中文路径、空格路径和长路径；
- 缺失素材；
- 移动导出目录后的行为。

采用 fixture/golden project 回归测试，并记录：

- 剪映准确版本；
- 操作系统；
- 测试日期；
- 支持矩阵；
- 已知限制。

## 11. MVP 实施顺序

1. 先完成中立时间线；
2. 完成稳定的 FFmpeg MP4 输出；
3. 输出媒体包、SRT 和镜头表；
4. 选择一个明确的 Windows 剪映桌面版本进行适配验证；
5. 实现能力检查和兼容报告；
6. 再扩展更多版本和字段。

在未完成真实版本样本验证前，不应把剪映导出标记为“稳定”。
